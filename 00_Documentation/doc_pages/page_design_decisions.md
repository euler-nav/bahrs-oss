\section sec_design_decisions_rte Runtime environment

\subsection subsec_design_decisions_port_protection Port access protection

-# SWC ports shall be private members of the CRte class.
-# Software components shall be friends of the CRte class.

\subsection subsec_design_decisions_port_data_types Software component port data types

Port data types shall inherit from @link NLibCommon::CSerializable @endlink and implement its virtual methods
@link NLibCommon::CSerializable::ToByteVector() @endlink and @link NLibCommon::CSerializable::FromByteVector() @endlink.
**Rationale:**
Easy serialization/deserialization of data stored in software component ports streamlines development process by simplifiying debugging and defect analyses.

@subsection subsec_design_decisions_rte_autogeneration Auto-generation of runtime environment

The @link CRte @endlink class, which implements the runtime environment (RTE), is automatically generated based on an RTE description provided in JSON format,
alongside template source and header files. Software component port data types can either be defined by the user or automatically generated by the RTE generator utility.
Additionally, the RTE generator can produce several supplementary source and header files required for the development tools used by the team.

**Rationale:**
The runtime environment is subject to frequent changes, such as the addition or removal of ports, modification of existing port data types, and the integration of
new software components. These modifications can involve tedious manual work and require high attention to ensure adherence to the [RTE design principles](@ref sec_design_decisions_rte).
Utilizing a code generation tool helps streamline the development process by automating these tasks, minimizing the risk of errors or deviations
from the established design principles, and ensuring consistent compliance with the project's architectural guidelines.
